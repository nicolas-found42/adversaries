# Council decision workspace redesign

Source: the 18-page UI review packet (02 Nov 2026), the three standalone HTML experiments in the review chat, and the subsequent screenshot-led critique. The courtroom experiment contributes structural ideas, not literal costume. The packet does not define convergence math, seven numbered regions, hex telemetry, ten summary tiles, or recordings A/B; do not invent those features.

## Acceptance inventory

- Execution review: practice and real mode, immutable question/attachments/role assignments/rounds; retained and remaining work; explicit paid-call approval; changed configuration invalidates approval; repeat activation cannot dispatch twice.
- Recovery: distinguish user stop, provider failure, unfinished replay, unreadable save, failed startup, and missing continuation configuration. Never call in-memory work durably saved without evidence. Reading and history replay never infer.
- Focused reading: compact global navigation; brief owns the default reading space; chronology co-located with argument; one primary scroll; all tasks reachable at narrow widths and enlarged text.
- Honest outcomes: execution completion is not consensus; model confidence is uncalibrated; debate labels do not verify claims; source occurrence is separate from factual verification; exports carry qualification.
- Claim inspection: retain full source text and source location; stable identity scoped to originating stage; inspect original/challenges/responses; return to the same claim/brief and scroll position; contextual diagnostics.
- Setup: optional framing prompts; six role selections; one to five rounds; provider readiness; attachment loading/ready/error/removal; practice mode makes no inference calls; real mode reviews recipients and document disclosure.
- History: readiness on every row; filter/search; timestamps; replay versus continuing/rerunning; incomplete and legacy saves remain readable.
- Visual system: readable widths, consistent type/spacing, clear primary actions, persistent selection distinct from focus, reduced motion, keyboard and accessibility names, long content/table handling.
- Engine/transport: reliable resume validation, safe request dispatch/cancellation and persistence; do not promise exact price, hard budget, external verification, or cancellation refunds without an implementation.
- Validation: meaningful state and transport tests, rendered wide/narrow fixtures, native/WASM build checks, all pre-commit gates, Jev evidence review. Human usability and platform screen-reader tests remain a release validation task, not something a model judgment can certify.

## Implementation record — input safety, provenance and recovery

- Native and browser preflight extracts text before approval, blocks missing/empty/unreadable documents, reports the 60,000-character limit, and lets the reader inspect the exact included text. PDF/DOCX/XLSX extraction is covered with the optional reader dependencies installed. A frozen, digest-checked snapshot travels on stdin to the engine and survives checkpoint replay; changing or deleting the original does not change the reviewed payload.
- Provider checks distinguish credential presence from model availability. A real run with missing credentials cannot be approved. No preflight constructs inference callers. Metadata/catalog requests are separate from inference.
- Atomic engine request reservation and bridge dispatch protection prevent retransmitting an approved request from repeating model stages or replacing its original process. Each new approval receives a new identity. Delayed cancellation is tied to its run identity. SSE decoding preserves Unicode split across arbitrary byte chunks.
- Resume validates an ordered, contiguous prefix against model and role assignments on both assigned and legacy plans. An actual engine/checkpoint integration test resumes at stages 3–6 after retaining stages 1–2. Continuation and a fresh run remain separate decisions.
- Reused claim labels retain separate origins. Ambiguous later references do not assign a verdict to multiple statements. Matched excerpts link to reviewed supplied text; an unavailable/unlocatable source is disclosed. Source inspection starts with the selected statement, not the stage sequence. Back/Escape restores the opener's focus, selection and scroll position.
- Completed stage payloads reach the UI before persistence: checkpoint/journal failure cannot hide an argument already generated. Only successful checkpoint notifications increase the saved-stage count. Failed initial storage starts no stage. A brief followed by save failure stays readable and offers a qualified copy rather than another inference request.
- History distinguishes an empty first launch from a listing/storage failure, preserves the existing decision/configuration when another save cannot open, and explains why opening a second session is unavailable during an active run. Legacy provider counts use the recorded plan rather than an assumed six-stage council.
- The lead parser handles both Markdown headings and the engine's inline **Recommendation:** / **Confidence:** form without rewriting the model's content. Unstructured output retains the original fallback.
